# Рекомендательная система выбора смартфона

Творческое задание по дисциплине «Рекомендательные системы и системы поддержки принятия решений», тема 1 «Выбор продукта (товара)».

Цель: система рекомендаций товаров на основе анализа потребностей и бюджета покупателя.

Веб-дашборд на Streamlit решает две задачи:

1. **Новый покупатель** (истории покупок нет) задаёт бюджет, обязательные требования и важность критериев. Система отсеивает неподходящие модели, ранжирует остальные методами AHP и TOPSIS, отмечает Парето-оптимальные и уточняет выбор по опыту похожих покупателей.
2. **Покупатель с историей** получает персональные рекомендации гибридной моделью: коллаборативная фильтрация плюс контентная.

| Метод | Где используется | Что делает |
|---|---|---|
| Ограничения (допустимые альтернативы) | Подбор | Бюджет, NFC, минимальная память, исключённые бренды |
| AHP (метод Саати) | Подбор | Веса критериев по баллам 1–5 или по матрице попарных сравнений, проверка CR < 0,1 |
| TOPSIS | Подбор | Близость модели к идеальному решению с весами из AHP |
| Парето | Подбор | Отметка недоминируемых моделей |
| K-means (k-means++) | Сегменты | Кластеризация 800 покупателей по покупательскому поведению, выбор k по силуэту |
| Item-kNN (неявная обратная связь) | Рекомендации | Товары, которые выбирают те же люди |
| iALS (матричная факторизация) | Рекомендации | Скрытые факторы предпочтений (Hu, Koren, Volinsky, 2008) |
| Контентная фильтрация | Рекомендации | Профиль покупателя по характеристикам понравившихся моделей, косинусная близость |
| Гибрид (взвешивание + переключение) | Рекомендации | α·CF + (1−α)·CB; при короткой истории CF = только item-kNN; без истории — TOPSIS + сегмент |
| SVD (Funk SVD) и item-kNN по оценкам | Сравнение | Прогноз величины оценки (RMSE, MAE) |

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется в браузере по адресу http://localhost:8501. Первый показ вкладки «Качество моделей» считается около 10 секунд, потом результат кэшируется.

## Как пользоваться

1. **Подбор под бюджет.** Задать бюджет, обязательные требования и важность критериев: баллами 1–5 или попарно по шкале Саати. Приложение покажет:
   - веса, λmax, CI и CR;
   - рекомендацию и топ-10 с сильными сторонами каждой модели;
   - сегмент похожих покупателей;
   - график «цена — соответствие требованиям» с Парето-оптимальными моделями и радар-диаграмму топ-3.

   Ползунок β задаёт, насколько учитывать опыт похожих покупателей. Подборку можно скачать в CSV.
2. **Сегменты покупателей.** Выбор k по силуэту и методу локтя, покупатели на двух главных компонентах, профили кластеров, тепловая карта центров.
3. **Персональные рекомендации.** Ввести ID покупателя (1–800) и посмотреть:
   - его историю оценок;
   - три списка: CF, CB и гибрид;
   - из чего складывается оценка гибрида;
   - объяснения вида «его часто выбирают те, кто купил X».

   Ползунок α задаёт долю коллаборативной части.
4. **Качество моделей.** Метрики на отложенной выборке, холодный старт, чувствительность гибрида к α, RMSE и MAE.
5. **Каталог.** Таблица и графики «цена — производительность», «популярность — средняя оценка».

Свой каталог можно загрузить в боковой панели («Свой CSV»). Обязательны столбцы `model`, `brand`, `price`. Критерии-столбцы: `antutu, camera, battery, ram, storage, refresh, screen, weight, nfc, year`. Подходит и CSV из русского Excel (разделитель «;», дробная часть через запятую). Для своего каталога работает подбор под бюджет. Рекомендации по истории строятся на встроенных данных.

## Данные

**Каталог** `data/catalog_smartphones.csv`: 58 реальных моделей смартфонов 15 брендов 2021–2025 годов, цены от 6 490 до 129 990 руб. Характеристики даны по спецификациям производителей. Производительность указана как ориентировочный балл AnTuTu v10 в тысячах. Цены ориентировочные: это порядок цен на маркетплейсах, а не прайс-лист на конкретную дату.

**Покупатели и оценки** (`data/users.csv`, `data/ratings.csv`) смоделированы скриптом `scripts/generate_data.py` (seed = 42). API Wildberries и Ozon не отдают историю покупок с идентификаторами людей, поэтому для коллаборативной фильтрации нужна модель поведения. Модель прозрачная:

- у каждого из 800 покупателей есть скрытый сегмент (экономный, геймер, фотограф, премиум, практичный), бюджет, личные веса критериев и симпатии к брендам;
- полезность модели = взвешенная сумма нормированных характеристик + симпатия к бренду − штраф за выход из бюджета;
- покупатель чаще оценивает подходящие и узнаваемые модели, а оценка 1–5 растёт с полезностью.

Получилось 11 990 оценок (≈15 на покупателя, матрица заполнена на 26%, средняя оценка 3,8). Скрытый сегмент методам не передаётся и используется только для проверки кластеризации (ARI).

## Результаты

Оценка выполнена на отложенной выборке: у каждого покупателя спрятано 20% оценок, релевантны спрятанные модели с оценкой 4–5, ранжируются все ещё не оценённые модели.

| Модель | Precision@10 | Recall@10 | NDCG@10 | HitRate@10 | Покрытие |
|---|---|---|---|---|---|
| Популярность | 0,123 | 0,574 | 0,403 | 0,685 | 0,45 |
| Контентная (CB) | 0,076 | 0,366 | 0,252 | 0,521 | 1,00 |
| SVD по оценкам | 0,039 | 0,191 | 0,130 | 0,254 | 0,91 |
| Item-kNN неявный (CF) | 0,172 | 0,820 | 0,636 | 0,901 | 0,84 |
| iALS (CF) | 0,179 | 0,855 | 0,630 | 0,921 | 0,98 |
| **Гибрид** | **0,181** | **0,865** | **0,666** | **0,931** | 0,95 |

- Гибрид лучше каждой своей части. При холодном старте (1–5 оценок у нового покупателя) он не хуже item-kNN и заметно лучше iALS и популярности.
- Модели, которые прогнозируют величину оценки (SVD: RMSE 0,935 против 0,970 у глобального среднего), плохо ранжируют. Для списка рекомендаций важнее угадать, что покупатель вообще выберет, поэтому используется неявная обратная связь.
- K-means: максимум силуэта при k = 3 (0,418). Сегменты: экономный (≈14 тыс. руб., аккумулятор), премиальный (≈54 тыс. руб., Apple и Samsung), средний (≈28 тыс. руб., экран, память, камера). ARI со скрытыми сегментами 0,38 при k = 3 и 0,50 при k = 4: геймеры и фотографы по покупкам похожи.

## Формулы

- **AHP:** w = среднее геометрическое строки / сумма; λmax = Σ (сумма столбца × вес); CI = (λmax − n) / (n − 1); CR = CI / ПСС.
- **TOPSIS:** r = x / √Σx², v = w·r, C = D⁻ / (D⁺ + D⁻).
- **K-means:** минимизация Σ‖x − центр кластера‖². Силуэт s = (b − a) / max(a, b).
- **Item-kNN:** s(i, j) = косинус векторов «кто выбрал» × n / (n + 10), где n — число общих покупателей. Оценка = Σ s(i, j) · r_uj / 5.
- **iALS:** p_ui = [r_ui > 0], c_ui = 1 + 2·r_ui. Минимизируется Σ c_ui (p_ui − x_u·y_i)² + λ(‖x‖² + ‖y‖²).
- **CB:** профиль = Σ (r_uj − r̄_u)·x_j, оценка = cos(профиль, x_i).
- **Гибрид:** α·CF + (1 − α)·CB, α = 0,9. CF = (kNN + iALS)/2 при 5+ оценках, иначе только kNN.
- **Подбор нового покупателя:** итог = (1 − β)·TOPSIS + β·популярность в сегменте.
- **Метрики:** Precision@k, Recall@k, NDCG@k = DCG/IDCG, HitRate@k, покрытие каталога, новизна = −log₂(доля оценок товара).

## Тесты

```bash
pytest
```

31 автотест:

- AHP сверяется с примером преподавателя из «Метод Саати.xls» (CR = 0,0116);
- K-means находит три разделённых облака точек;
- коллаборативные модели находят товары, которые покупают вместе;
- метрики сверяются с ручным расчётом;
- гибрид лучший по NDCG@10;
- некорректный CSV отклоняется с понятной ошибкой;
- весь интерфейс прогоняется без браузера (streamlit.testing).
